# Open Second Brain feature catalog

Every feature of Open Second Brain in one line, grouped by area; `kw:` lists the words outsiders use for it.
Generated by `bun run catalog:build` from the area files in this folder; never edit this file by hand.
The area file named in each heading holds a feature's capabilities, limits, surfaces, docs and code.

## capture - Capture (capture.json)

- `feedback-signals` — Agents record taste signals, applied or violated evidence and log milestones; reminders keep them doing it. | kw: preference learning, feedback capture, memory write tool, explicit memory, user corrections
- `session-capture` — Lifecycle hooks turn prompt markers, facts and brain_feedback calls into signals and log session events. | kw: automatic memory capture, conversation logging, lifecycle hooks, passive capture, transcript mining
- `inline-markers` — @osb markers and inline citations in notes become captured items, dated events or front matter write-backs. | kw: inline tags, annotation syntax, frontmatter write-back, source citations, note markup
- `inbox-capture` — Stages captures from the terminal or a Telegram bot and routes them to sources, notes or obligations. | kw: quick capture, inbox triage, mobile capture, chat bot capture, fleeting notes
- `session-summaries` — Stores a structured session digest of decisions, learnings and next steps, and writes handoff notes. | kw: session summary, conversation summarization, handoff notes, end-of-session checkpoint, episodic memory

## consolidation - Consolidation and learning (consolidation.json)

- `dream-pass` — Promotes repeated signals to rules, confirms, quarantines and retires them by evidence, and replays missed days. | kw: memory consolidation, sleep-time compute, reflection, preference learning, rule induction
- `cross-topic-rules` [optional] — Optionally promotes one rule a day per owner from confirmed rules that repeat across topics, citing each source. | kw: rule generalization, pattern mining, cross-domain transfer, knowledge abstraction, inductive learning
- `dream-owner` — One device and agent run the live dream passes for a brain; other machines preview, and the role can move. | kw: leader election, single writer, job ownership, failover, multi-device sync
- `dream-agent` — Model work of a dream pass waits in a queue for the operator's own agent command, which is set and verified per machine. | kw: job queue, background agent, work leasing, headless agent, process supervision
- `dream-drafts` [optional] — Model-written text from a dream pass records its agent and model and can be held for operator approval. | kw: human-in-the-loop, approval workflow, draft review, provenance, authorship attribution
- `preference-lifecycle` — Reads, pins, rejects, merges and expires preferences, with their evidence trail and an audit of content changes. | kw: memory management, audit trail, rule pinning, memory expiry, deduplication
- `memory-corrections` — Tombstones, supersedes or time-replaces any memory and reports the blast radius of a correction first. | kw: memory correction, soft delete, belief revision, bi-temporal validity, fact invalidation
- `lessons` — Scores outcome-tagged lessons into a digest and promotes approved ones into managed blocks of agent rule files. | kw: lessons learned, outcome tracking, experience replay, self-improving agent, agent rules file
- `decision-models` [optional] — An optional typed judgment model that reranks, filters and checks candidates; each use runs off, shadow or enforce. | kw: llm as judge, reranking, classifier, shadow mode, decision threshold
- `judgment-commands` — Hands a judgment call to an operator-configured command as JSON on stdin and reads its JSON verdict back. | kw: llm as judge, external evaluator, command hook, pluggable judge, json over stdio

## delivery - Context delivery (delivery.json)

- `active-preferences` — Sessions start with confirmed rules, recent retirements, topic heads and pinned context; subagents skip the last two. | kw: memory injection, custom instructions, session bootstrap, system prompt, provenance trust ordering
- `pinned-context` — A current-task scratchpad that survives context rotation without becoming a permanent preference. | kw: working memory, scratchpad, memory block, task notes, sticky context
- `standing-rules` — Operator-written rules, vault-wide or scoped to a project, harness or host, delivered to every session. | kw: custom instructions, system prompt, project rules, agent rules file, constitution
- `context-packs` — Returns preference and retired-rule pages by tier and recency under a token budget, with presets and a size report. | kw: context packing, token budget, context window management, context engineering, retrieval budget
- `prompt-recall` [optional] — Optional hooks inject a bounded recall brief per prompt or a link-graph map on a cadence, plus a warm session cache. | kw: proactive recall, automatic retrieval, prompt augmentation, retrieval-augmented generation, context injection
- `cross-agent-updates` — Shows a session what other agents and machines recorded on its topics and in the shared log since it last looked. | kw: shared memory, multi-agent coordination, activity feed, change feed, cross-session sync
- `compaction-survival` — Builds a pre-compression rules addendum, extracts labelled lines before compaction and re-asserts drifted pins after. | kw: context compaction, context compression, memory flush, summarization, context rot
- `context-receipts` — Records what context was delivered, whether it was used, its token impact and generation usage, and joins them by id. | kw: context provenance, observability, llm tracing, audit trail, token accounting

## knowledge - Structured knowledge (knowledge.json)

- `topics` — One page per theme with status, goal, milestones, decisions and open questions, kept by agents and the dream pass. | kw: topic pages, thematic grouping, project memory, living documents, work log
- `entities` — Canonical people, projects and things with aliases, relations and subject profiles. | kw: entity resolution, entity registry, alias resolution, knowledge graph, entity linking
- `claim-ledger` — An append-only truth ledger of entity claims with validity windows, and a claim graph read from memory front matter. | kw: temporal knowledge graph, fact ledger, bitemporal facts, truth maintenance, conflict detection
- `decision-records` — Decision notes with options, assumptions, outcomes and ratings, open decisions, persona panels and design notes. | kw: decision log, architecture decision records, decision journal, pre-mortem, outcome tracking
- `tensions` — Detects contradictions in the operator's notes and tracks each one from open to confirmed, dismissed or resolved. | kw: contradiction detection, inconsistency detection, belief revision, conflict triage, knowledge consistency
- `dead-ends` — Records approaches tried and failed, with the reason; search and the session-start lessons digest surface them. | kw: negative knowledge, failed approaches, lessons learned, anti-patterns, mistake log
- `schema-packs` — The record vocabulary of a brain: types, link types, labels and typed attributes, changed through audited mutations. | kw: ontology, controlled vocabulary, metadata schema, taxonomy, typed properties
- `link-graph` — Backlinks, unlinked mentions, proposed bridge links, communities, hub coverage audits and a graph explorer. | kw: knowledge graph, backlinks, link suggestions, community detection, maps of content
- `synthesis-and-research` — Topic dossiers with agreements, contradictions and gaps, cited research reports, idea discovery and lineage. | kw: research synthesis, knowledge gaps, contradiction detection, provenance tracing, cited reports

## planning - Briefs and planning (planning.json)

- `briefs` — Morning, daily, weekly and monthly briefs, a today dashboard, an operator summary and a logging discipline report. | kw: daily digest, morning briefing, weekly review, activity summary, dashboard
- `memory-analytics` — Event timelines, how a belief evolved, attention recipes over open loops, and concept clusters. | kw: memory analytics, timeline view, belief revision history, concept clustering, attention management
- `proactive-triggers` — A deduplicated queue of grounded prompts to act, snooze or dismiss, and a projection of what comes due. | kw: proactive suggestions, nudges, notification queue, snooze, reminders
- `commitments` — Recurring obligations with next-due dates, quoted pledges with due dates, agendas from events, counterparty briefs. | kw: recurring tasks, commitment tracking, promise tracking, calendar agenda, meeting prep
- `current-intentions` — Per-workstream current-intention documents with history, and an overwrite-only lane for the exact current state. | kw: working memory, current focus, goal tracking, state tracking, scratchpad
- `knowledge-gaps` [optional] — Ranks recurring queries the vault answers poorly and can surface them as an agenda at session start. | kw: knowledge gaps, unanswered queries, content gap analysis, search analytics, query logs

## search - Search and recall (search.json)

- `vault-search` — Full-text search over notes and brain memory with explanations, compact cards, drill-down and a recall gate. | kw: full-text search, bm25, hybrid retrieval, progressive disclosure, recall gating
- `search-index` — Builds, refreshes, rebuilds, watches and diagnoses the local full-text index that search reads. | kw: incremental indexing, full-text index, index rebuild, file watcher, sqlite fts5
- `semantic-search` [optional] — An optional embedding lane beside keyword search, with provider profiles and vector backfill. | kw: vector search, embeddings, dense retrieval, semantic similarity, embedding provider
- `search-reranking` [optional] — An optional reranker re-scores the top results, with provider profiles, a fit check and a labelled benchmark. | kw: reranking, cross-encoder, second-stage ranking, llm reranker, rank correlation
- `relational-recall` [optional] — An optional fourth search arm that walks typed links and entity co-occurrence under width budgets. | kw: graph traversal, multi-hop retrieval, knowledge graph retrieval, graphrag, typed relations
- `recall-tuning` — Relevance feedback trains hybrid ranking weights, a session focus biases recall, and tuning grid-searches parameters. | kw: relevance feedback, learning to rank, hyperparameter tuning, query biasing, personalized ranking
- `recall-evaluation` — Scores recall against fixed query datasets and fixture vaults, and records opt-in recall telemetry. | kw: retrieval evaluation, recall benchmark, memory benchmark, mrr, hit rate
- `session-recall` — Imports agent transcripts already on disk, searches and expands them, and mines their user turns for signals. | kw: conversation history, episodic memory, transcript ingestion, chat log search, session memory

## setup - Setup and host integration (setup.json)

- `guided-setup` — Configures the machine and the brain, connects one agent host and verifies it; a first-run checklist shows what is left. | kw: installation wizard, first-run setup, onboarding checklist, quickstart, init command
- `host-install` — Writes, checks, updates and removes the integration for each supported agent host; Aider runs inside a memory wrapper. | kw: mcp client configuration, editor integration, plugin installer, config merge, uninstaller
- `hermes-memory-provider` — Runs Open Second Brain as the Hermes Agent memory provider and stores Hermes built-in memory writes in the brain. | kw: memory provider, memory plugin, agent memory backend, context prefetch, memory hooks
- `openclaw-plugin` — A native OpenClaw plugin with status, page listing and health tools and a per-turn agent identity reminder. | kw: native plugin, agent plugin, tool registration, prompt hook, identity reminder
- `mcp-server` — Serves the tools over stdio or HTTP with tool profiles, a two-pass catalog, parked large results and latency metrics. | kw: mcp server, model context protocol, tool filtering, lazy tool loading, result truncation
- `mcp-access-tokens` [optional] — Named per-agent tokens for the HTTP transport, and one-command provisioning of a host, optionally with its token. | kw: api tokens, bearer authentication, per-agent credentials, token rotation, credential provisioning
- `install-health` — Reports configuration, vault and plugin health, the installed version and a redacted config snapshot. | kw: health check, diagnostics, doctor command, self-test, readiness probe
- `mcp-server-safeguards` — The MCP server refuses unknown arguments, survives stray faults, drains on shutdown and stops writing once outdated. | kw: graceful shutdown, input validation, fault tolerance, crash resilience, version skew

## skills - Skills and procedural memory (skills.json)

- `skill-learning` — Proposes skills from repeated work and mature pages, and gates skill rewrites on a frozen benchmark. | kw: skill learning, procedure mining, workflow extraction, prompt optimization, regression gate
- `procedural-memory` — An index of procedures with usage and outcomes, a procedural graph with hints, and recurrence diagnostics. | kw: procedural memory, runbook index, workflow memory, success-rate ranking, evidence counting

## sources - Sources, code and portability (sources.json)

- `source-ingest` — Writes an agent's summary and entities for a document or URL into pages, plans folder ingests and removes a source. | kw: document ingestion, entity extraction, incremental ingest, batch ingestion, source provenance
- `source-distillation` — Condenses a source into atomic claims whose quotes are checked against the source and cited by block. | kw: atomic notes, claim extraction, quote verification, citation checking, block references
- `project-history` — Git history and code structure become vault records and notes; note history and file mentions are read back. | kw: git history mining, commit log ingestion, architecture decision records, repository memory, code structure extraction
- `codegraph-partner` [optional] — Detects a codegraph index of the code project and reports it, so agents use it for structural code questions. | kw: code graph, code intelligence, symbol index, call graph, impact analysis
- `knowledge-export` — Exports and imports preferences, the knowledge graph, Open Knowledge Format bundles, bank bundles and knowledge packs. | kw: data export, backup and restore, knowledge interchange, data portability, graph export

## store - Brain store and maintenance (store.json)

- `brain-store` — Append-only shared and private record partitions that several machines can sync, with device, partition and shard care. | kw: local-first sync, append-only log, event sourcing, hybrid logical clock, crdt
- `store-migration` — Moves a legacy brain into the store, upgrades release-owned files and relocates vault state, with dry runs. | kw: data migration, schema migration, dry run, rollback, automatic upgrade
- `shared-settings` — Settings every machine of a brain agrees on, read and changed by name, with operator values protected from agents. | kw: shared configuration, config sync, last-writer-wins register, settings management, access policy
- `storage-report` — Per-surface storage census with a growth forecast against a cap, and compaction of expired receipt records. | kw: disk usage, capacity planning, storage quota, log compaction, growth forecast
- `maintenance-lane` — A lease-guarded quiet-window lane that runs dream, reindex, links and custom tasks, or prints a cron recipe. | kw: background jobs, scheduled maintenance, job scheduler, cron, distributed lease
- `brain-health` — Invariant checks with safe repairs, semantic health, recovery probes and an operator status with next commands. | kw: health check, integrity check, self-diagnostics, fsck, contradiction detection
- `memory-hygiene` — Finds contested, duplicate, stale and unused memories and broken pages, and applies only the fixes chosen. | kw: memory deduplication, stale memory detection, conflict resolution, knowledge base cleanup, linting

## trust - Integrity, audit and safety (trust.json)

- `write-ledger` — Records each note write by agent and device with a before-image, and plans a sealed undo per agent or path. | kw: audit log, write attribution, undo, tamper-evident log, hash chain
- `write-controls` — A permissions document, an owner-write gate, a global write freeze and host deny rules that keep agents off brain files. | kw: access control, write permissions, policy engine, kill switch, read-only mode
- `staged-review` [optional] — Optionally stages agent note creates and ingest pages for operator approval before they are published. | kw: human in the loop, approval queue, moderation queue, staged writes, review workflow
- `store-attestations` — Ed25519-signed attestations of the legacy Brain log heads and ledgers, verified shard by shard. | kw: digital signature, integrity attestation, tamper detection, signed checkpoint, ed25519
- `secret-custody` — Credentials kept encrypted behind a capability gate and referenced as $secret:NAME in configuration. | kw: secrets management, credential vault, encrypted storage, secret injection, api key storage
- `snapshots-rollback` — Recovery points before brain mutations, with diff and restore; on a store-switched machine rollback refuses. | kw: backup, restore point, point-in-time recovery, rollback, versioning
- `agent-provenance` — Shows which agent contributed which signals and notes, compares agents, and groups signals by source. | kw: data provenance, multi-agent attribution, lineage, contribution tracking, source tracking
- `answer-quote-check` — At the end of a turn, checks the agent's quoted spans against the notes the turn actually had. | kw: citation verification, hallucination detection, grounding check, quote verification, answer faithfulness
- `secret-redaction` — Masks secret-shaped values in what is written, logged or reported; every export path passes one egress guard. | kw: secret redaction, data loss prevention, egress control, credential scrubbing, log sanitization
- `write-safety` — Keeps every write inside the vault and atomic, serializes writers with locks and refuses links planted in local state. | kw: path traversal protection, atomic file writes, file locking, symlink attack protection, crash safety
- `agent-identity` — Names the agent behind signals, evidence and log lines from an argument, a token or the config; stamps the process kind. | kw: agent identity, write attribution, origin tracking, subagent attribution, identity binding
- `remote-read-reservation` — Private pages and private-partition lane entries are withheld from remote callers; reach is a transport fact. | kw: private notes, remote access restriction, data classification, visibility labels, access control

- `write-sessions` — A prompt, validate and approve cycle for model-written artifacts and decision panels, independent of the provider. | kw: structured output validation, self-correction loop, provider-agnostic generation, multi-perspective review, decision panel
- `human-view` — Renders plain Markdown pages of rules, history, decisions and topics; editing a page records a human correction. | kw: human-readable export, two-way sync, markdown rendering, editable memory, user corrections
- `vault-scope` — Which vault paths are read, ignored or indexed, the folder role map, one-path inspection and a page listing. | kw: ignore rules, include paths, indexing scope, folder roles, path filtering
- `multi-vault` — Named vault profiles, project directories linked to their vault, and other vaults read as recall sources. | kw: multiple workspaces, workspace switching, cross-vault search, federated search, project linking
