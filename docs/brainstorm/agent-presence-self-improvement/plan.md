# Agent presence and self-improvement - implementation plan

Four implementation lanes with strictly disjoint file ownership plus one integrator. Each task is TDD-ready: write the failing test first, run it and see the expected failure, implement until green, refactor green, then run the repo formatter (`./node_modules/.bin/oxfmt`, not `bunx oxfmt`) and the repo lint on the task's own files before every commit, and commit only that task's own files with `git commit --only <paths>` (never a plain `git add` + `git commit`). Each lane runs ONLY its own new or changed test files locally (never the full suite); the integrator runs the full gates. Test runs use a throwaway HOME (`env HOME=$(mktemp -d) bun test <paths>`). Version bump, CHANGELOG assembly and the release-wide docs pass are the pr-prepare phase and are intentionally absent here.

Staged commit order: pure modules commit FIRST so dependent lanes unblock - Lane B's Task B1 (the shared writer) and Lane A's Tasks A1-A2 (the pure scoring leaves) are the earliest commits on the branch; Lane C may not start until B1's commit lands; Lane D is independent of everything.

Dependency-wait rule: a lane whose task depends on another lane's committed file polls `git log -- <file>` for the upstream lane's commit every 30 seconds, for at most 12 minutes. If the commit has not landed when the cap expires, the lane STOPS and reports which pinned-contract file it is waiting on; it never builds against uncommitted code and never re-implements another lane's module locally.
