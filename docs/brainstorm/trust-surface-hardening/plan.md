Notes on the two deliberate ownership placements:

- **Egress split.** `src/core/egress/guard.ts` is Lane B's (resolver literals wiring); `src/core/egress/registry.ts` and `tests/core/architecture/egress-census.test.ts` are Lane A's, because the credential-bundle export destination is the wave's only new egress site. The census asserts both directions (a site's module must be in the population), so Lane A's A2 lands the `--out` flag and the registry entry and the census rows in ONE commit — never split across commits.
- **Lane A exports, Lane B consumes.** Lane A's A1 ships a read-only resolve export on `src/core/brain/secrets/store.ts` (no `last_used_at` stamp, no exec audit). Lane B's resolver calls that export through the module's public surface only; it must never edit secrets-module files.

**Commit discipline.** Every lane commits with `git commit --only <paths>` — stage and commit in ONE step. Never `git add` files (shared or not) followed by a plain `git commit`; `--only` is what keeps a lane from sweeping up a sibling's in-flight work.

**Format and lint before every commit.** Run `./node_modules/.bin/oxfmt` and `./node_modules/.bin/oxlint` on YOUR files only, before every commit.

**The pre-commit hook checks the whole tree.** `.githooks/pre-commit` runs `bun run fmt:check` (and mirror checks) over the entire worktree, not just your paths. If it blocks on a sibling lane's transient state, wait 30 s and retry, up to 5 attempts. Never pass `--no-verify`.

**Windows-safe tests.** No chmod-deny assertions without a `tests/helpers/platform.ts` skip guard (`IS_WINDOWS`, `RUNNING_AS_ROOT`, and the chmod-cannot-deny constant). Normalize path separators in every path assertion (compare on `path.sep`-normalized or forward-slash forms). The existing secrets suites already show the `IS_WINDOWS` skip pattern.

**No scanner false positives.** No identifier may contain the substring `secret` immediately before a quoted value of 8+ characters (plugin scanners flag it). Use names in the `PRIVATE_PATH` / `credentialRef` style. In tests, assemble credential-shaped literals at runtime via `tests/helpers/fake-credentials.ts` instead of writing literal-looking values.

**No hardcoded natural-language phrases.** All operator-facing strings are English constants hoisted next to their siblings; error and reason tokens come from closed tables, never assembled from prose; errors surface by name (stable `code`/token), never as ad-hoc sentences alone.

**Opt-in flags.** Any new config flag is opt-in with defaults preserving current behavior byte-for-byte. The wave's write-path changes are card-mandated (rejection is the feature), and each is covered by its own failing-test-first proof below.
