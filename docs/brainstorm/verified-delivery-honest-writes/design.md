# Cycle 20261026 - verified delivery and honest writes: what the delivery trims, what the reply contained, what the store refuses to leak, and what every write surface admits

**Status:** draft
**Author:** orchestrator (via feature-release-playbook)
**Audience:** implementation

## Problem statement

Open Second Brain's delivery and write surfaces stop one step short of the truth in eight places. Delivery bounds context packs with a tier-dominant budget, so a peripheral page restating the agent's question is dropped before a core page that does not, and nothing records whether an injected memory ever surfaced in the agent's reply. The preferences bank and llms-txt export filter by status only, so a rule the operator marked private rides out to shared surfaces that every other exporter already blocks. Dead extraction writes leave durable letters that name their payload but offer no classification and no one-command recovery, and an agent that patches vault files outside a hook or tool call has no gate that exits non-zero. The operator status says nothing about who holds the writer lock or that the status caller itself is read-only, folder reorganization must move notes one file at a time through a surface that refuses directory changes, and doctor resolves client commands without reporting which version of each client answered. Every one of the eight features replaces one of those silences with a measured, classified or scope-honest fact.

## Scope

Eight features, each with its kanban card, grouped into four implementation lanes:

- `t_cb6a5558` (Lane A) - Score-aware tail trim for delivered evidence: a config-gated trim after the tier gate that keeps the top 3 delivered items and any tail item whose query-term overlap nearly matches the top hit, drops the rest whole as a new `tail-trim` skip reason, and offers the freed budget back to `over-budget` candidates in priority order; telemetry reports dropped, kept-by-query-terms, rescued and tokens-saved.
- `t_f8510c55` (Lane A) - Reply-presence receipts: the answer-quote-check Stop hook folds per-injected-note presence verdicts (including an explicit `absent` for notes no reply span touched) into a sibling continuity record joined to the context receipt by `session_id`; the `session_inject` receipt gains its missing `session_id`.
- `t_b88c2190` (Lane B) - The preferences bank/llms-txt export learns the existing privacy deny markers: `visibility: private` and the informal `access`/`confidentiality`/`sensitivity` markers deny a preference from every shared lane (json export, llms-txt, bank bundle, knowledge pack), each omission named, with no override flag.
- `t_50794f57` (Lane C) - One-command recovery for dead extraction writes: dead-letter schema v2 freezes the payload at failure time; a classifier labels every row `recover`, `pending`, `re-extract`, `not_recoverable` or `resolved` with the exact copy-paste command; `o2b brain dead-letters recover` re-runs the recorded payload at current vault state behind the established consent ladder.
- `t_dc782fd5` (Lane C) - Standalone validation gate: `o2b brain validate --paths <p>... | --dirty` runs the exact write-receipt page-lint vocabulary over a caller-named page set or every git-dirty note and maps findings to doctor's exit-code contract, so an unhooked agent or cron script can block its own commit.
- `t_9571a47f` (Lane D) - Folder-level note moves and renames: two new actions on the existing note-lifecycle surface move or rename a whole folder, refuse occupied destinations before the first byte moves, and rewrite inbound path-spelled wikilinks in a single pass over the successfully moved set.
- `t_cfe2ce5d` (Lane D) - Status store-ownership honesty: the operator snapshot gains a `store` group reporting the search writer lock as `held`/`free`/`unknown` with age, an owner field that truthfully reads null because the lock record carries no identity, and a `thisCaller: read-only` statement.
- `t_8e49ec96` (Lane D) - Doctor client versions: a `client_versions` readiness probe beside `registered_commands` asks each manifest-recorded client its version with a fail-soft read-only async spawn and grades rows pass/unknown/skipped, never fail.

Plus the integrator/docs phase (outside the four lanes): `docs/cli-reference.md`, `docs/mcp.md`, `CHANGELOG.md`, and the two wiring-file description lines that belong to Lane C-owned files.

## Out of scope

- Writer-lock owner identity stamping (an owner record written inside the lock directory at acquire time) - deferred; v1 reports `writerLockOwner: null` and says so in the renderer rather than inventing a holder. The brain-lane `.lock` files stamp a pid, but no surface reads it back and the status field is scoped to the search writer lock only, stated in the docblock.
- Dead-letter deletion on recovery - the retention rule stands: nothing in the project deletes a dead letter; a successful recovery says so and names the file the operator may delete by hand.
- A CLI flag for the tail trim - the established MCP-first precedent (`query_mode`, packing-policy, entity-facts): the config key and env var resolve for MCP callers; the CLI context-pack verb reads no config gates today and gains none here.
- Extending the trim to the `packingPolicy` branch of `packContext` - the unified path only in v1, with a note in the module where the policy branch begins.
- Reply presence for the `pre_compress` injection lane - the card and the Stop hook cover the recall/active/subagent phases; pre-compression presence is a follow-up.
- Inventing a privacy class for preferences - the export teaches the existing deny markers (`pageVisibility` token plus `hasPrivacyDenyMarker`); the knowledge pack already blocks class-marked pages.
- Auto-fix in the validate gate - report-only in v1; findings carry their existing `next_command` pointers to `brain doctor --repair` and `brain lint --consolidate --apply`, and no third fix vocabulary is grown.
- A minimum-version table for doctor client versions - no `minVersion` column, no config surface; the grading vocabulary stays without `fail`.
- Lane edits to `docs/cli-reference.md`, `docs/mcp.md` and `CHANGELOG.md` - all integrator/docs phase.
- The doctor message touch-up in `src/core/brain/doctor/privacy-marker-check.ts` (naming the preference export as a marker reader) - deferred as behavior-neutral; the existing sentence stays true after this change.
- Changing the locking strategy, the append-only continuity store, or the closed dead-letter lane union.

## Chosen approach

Four parallel lanes on provably disjoint file sets, each reusing the seam its recon verified rather than building a parallel surface. Lane A reuses the ranked-mode jaccard kernel inside the unified `packContext` walker for the trim (flag off stays byte-identical) and the existing Stop-hook check loop for presence, emitting an append-only sibling record because the continuity store cannot amend the receipt written at injection time. Lane B computes denials once at the collector seam where the frontmatter map is already parsed, keeps `rows` complete for the import topic maps, and lets the json envelope, llms-txt variant, bank bundle and knowledge pack each name what they leave out. Lane C adds the two new flat verbs (`dead-letters`, `validate`) with a core classifier and a tiny git-dirty helper, owning all four CLI wiring files exclusively. Lane D extends the note-lifecycle action vocabulary and the operator snapshot and the readiness probe registry - no new verbs, so it needs none of the wiring files. Every destructive path follows the repo's established consent ladder (dry-run default, headless `--yes`, frozen-vault and vault-identity guards), and every new reportable fact is named in an existing reporting contract (`omitted`/`blocked` arrays, skip reasons with gap telemetry, readiness rows, snapshot groups) rather than a second vocabulary.

## Design decisions

### Lane A - delivery (`t_cb6a5558`, `t_f8510c55`)

1. Trim lives after the unified walker, reusing comparator scores. The trim applies once `opts.tailTrim` is on and a query is present: the first 3 delivered items are immune (module constant `CONTEXT_PACK_TAIL_TRIM_KEEP`), a tail item whose jaccard score against the query is at least `TAIL_TRIM_KEEP_FRACTION` (0.8) of the top delivered score is kept, everything lower is dropped whole with a new `"tail-trim"` skip reason, and the freed budget is offered to `over-budget` candidates in priority order - rescue is the only path across tiers, bounded by the same `maxTokens`, and never reorders the attention item. In `ranked` mode the scores already sit in `relevanceById` and are reused; in other modes they are computed under the flag only. Rationale: the validator's "after the tier gate" phrasing and the named-constant-not-knob precedent (`CONTEXT_PACK_ENTITY_FACTS_MAX_ENTITIES`); in-walker placement keeps the off-path byte-identical and makes the receipt correct for free, since finalize maps `report.items`.
2. Trim reporting rides the existing conditional-member shape: `tailTrim?: { dropped; keptByQueryTerms; rescued; tokensSaved }` on `ContextPackReport`, attached in `finalizeContextPackReport` only when the option ran, with the counters echoed into `contextPackBudgetMetadata` so receipt `budget` and telemetry `metadata` carry them and `contextPackGaps` surfaces the new reason as gap `tail_trim` automatically. Names echo upstream's `delivery.tail_trim` without copying its envelope.
3. Flag resolver follows the precedent family: `resolveTailTrimContextPack` (config key `tail_trim_context_pack`, env `OPEN_SECOND_BRAIN_TAIL_TRIM_CONTEXT_PACK`) beside the entity-facts resolver at `src/core/config.ts:862-876`, default off, absent option documented as byte-identical.
4. Presence is a sibling continuity record, not a receipt amendment. The continuity ledger is append-only, so the Stop hook cannot revise the receipt written at injection time; instead it appends `kind: "reply_presence"` with `{ session_id, per-note verdicts, checked, source_hash? }`, and the receipt read surface gains a conditional join. The new kind joins `CONTINUITY_RECORD_KINDS` (same-edit rule) and gets a keep row in `FOLDABLE_CONTINUITY_KINDS`' sibling `KEPT_CONTINUITY_KINDS` - the fold-decision census fails on any kind without exactly one decision, and per-turn verdict rows are not fold candidates in v1.
5. Per-note outcomes reuse `ANSWER_QUOTE_VERDICT`, extended with `absent`: a note at least one reply span verified against reads `verified`; a note whose spans all miss reads its strongest miss verdict; a note no span touched reads `absent` - the row this feature exists to surface. One vocabulary, census-silent (the census entry self-derives from the constant); no second per-note set.
6. The join key is fixed at the source: `hooks/active-inject.ts` adds `sessionId` to the `session_inject` receipt (additive payload member), so receipt-to-presence joins do not depend on time windows. Where no session id exists on either side the read reports `unjoined` - honest absence, never an inferred match - and the join runs at the caller's reach: a note row the reach view hides is dropped from `per_note` and counted in `withheld`, so a filtered join never reads as a smaller check (the receipts-reach clause in the follow-up docs wave names this). Presence rides the existing per-phase `quote_check.*` modes (off/shadow/enforce, default shadow): no new config key, and operators who want silence set the phase off. Codex and grok stay annotation-silent as today, but the presence record writes wherever a transcript exists; `hooks/README.md` states this beside the existing annotation caveat.

### Lane B - export privacy (`t_b88c2190`)

7. Denial is computed once at the collector seam. `collectPreferenceRows` already holds the parsed frontmatter map at `src/core/brain/export.ts:269` and discards it; the denied array is computed from `hasPrivacyDenyMarker(meta)` and `pageVisibility(meta)` right there - no extra file read. `rows` stays complete because the import-side topic maps (`preference-restore.ts:592`, `knowledge-pack.ts:878`) must keep seeing every row; denial is a report beside the rows, not a filter inside the collector.
8. The deny is unconditional and named everywhere. There is no `--include-private` remedy (the knowledge pack carries none for its visibility blocks); a deny reason is `"visibility"` matching `pageBlockReason`'s vocabulary. The json envelope gains `omitted: [{id, reason}]`, absent when empty so the byte-identity redaction fixtures hold and the schema stays 1 (additive per the module's own versioning rule); llms-txt gains a detailed `{text, omitted}` variant with the stable string signature delegating to it (SDK stability); the export verb writes a stderr omission notice in the `contentClassOmissionNotice` shape whose remedy sentence names the reservation key, not a flag.
9. Shared surfaces follow so no two exporters disagree about the same directory: the bank bundle filters denied preferences and `brain bank-export` names the omissions on stderr (same shape as its existing content-class notice), and the knowledge pack converts collector denials into `blocked` entries `{kind: "preference", id, reason: "visibility"}` so its name-every-omission contract holds. A denied preference cannot ride redacted (the pack carries preferences with empty body), so this is drop-and-name.

### Lane C - capture writes (`t_50794f57`, `t_dc782fd5`)

10. Schema v2 freezes the payload at failure time. `DEAD_LETTER_SCHEMA_VERSION` bumps to 2 with an optional `payload` field (the validated items array, bounded by the existing 12-item per-session cap) written by `extract-signals.ts` when the mid-payload write throws; parsing stays strict per version, v1 letters keep parsing and classify as `re-extract`, unknown versions still refuse. No config key gates capture - the growth is small JSON and a knob here would silently downgrade the one fact recovery depends on.
11. The classifier has five honest states. `recover` (v2 payload, session still capture-classified, missing items not already deduped away), `pending` (staged items sit in the write-approval queue; the command names `brain pending apply`), `re-extract` (a payload-less v1 letter, or a frozen payload that no longer passes the lane's own shape and semantic validation; the command names `brain extract-signals <reference>`), `not_recoverable` (session unknown or boundary now refuses; no command, reason rendered), and `resolved` (every missing key now exists on disk) - the fifth state is required by the retention rule, else a reconciled row reads as still-broken forever. Unknown future lanes refuse by name as `not_recoverable`; the lane union stays closed on purpose.
12. Re-admission means re-run at current state, never at a recorded revision. The extraction-signal lane carries no revision counter - its concurrency story is the content-derived dedup hash plus atomic writes - so `recover --apply` calls `commitExtractedSignals` with exactly the MISSING items the letter names - never the whole payload, which would resurrect a delivered item an operator later removed (a deleted signal, a rejected queue row the dedup index never walks) - and lets it re-derive the capture boundary, dedup index and staging lane at call time; nothing stale is replayed by construction. `expectRevision` becomes load-bearing only if a preference-writing lane ever joins the union.
13. `o2b brain dead-letters` is a new flat verb (list default, `show <id>`, `recover <id>`): dry-run default with per-item verdicts, `--apply` requiring `--yes` under `--json` or non-TTY (the `brain lint`/`brain doctor --repair` rule), frozen-vault and vault-identity guards inherited, and the record id serving as the pin (the `writes revert --apply <digest>` pattern). The record's `DIAGNOSTIC_SIGNALS` entry points the `ExtractSignalsWriteError` message at the surface so the MCP error boundary - which never sees the typed write error today - can name the next command.
14. `o2b brain validate` is read-only and non-interactive by construction. Selection is exactly one of `--paths` (vault-relative, canonicalized, escape refused by name) or `--dirty` (a new tiny helper running `git status --porcelain` on the vault, including modified, added and untracked Markdown - an agent-created new note is exactly the target population; a non-worktree vault is a named refusal with exit 2, never a silent clean pass). Checks reuse `lintWrittenPages` verbatim - the write-receipt vocabulary plus `validateArtifact`'s error-severity document checks, and nothing new. Exit contract byte-for-byte doctor's lint ladder: errors or an unreadable named page 1 (a gate that could not read what it was pointed at may not report clean), `--strict` warnings 2, clean 0; exit 2 is SHARED with the verb's own usage refusals - the non-worktree `--dirty` refusal, an escaping `--paths` value, a bad selector - the same overlap doctor's usage paths accept, and a cron caller distinguishes them by the printed reason, not the code alone; `--json` reuses `PageLintReport` field names with no advisory-rail lines. The documented split keeps it from duplicating doctor: doctor is the whole-vault structural invariant pass with repair modes; validate is per-page authored-content lint over a named subset with the exit code as the product.

### Lane D - operator surfaces (`t_9571a47f`, `t_cfe2ce5d`, `t_8e49ec96`)

15. Folder moves are two new actions on the existing note-lifecycle surface, split from day one: `move-folder <folder> <toDir>` (destination parent must differ) and `rename-folder <folder> <newName>` (single segment, same parent), mirroring the file surface's rename/move discipline that catches caller mistakes. The vocabulary extends `NOTE_LIFECYCLE_ACTION` so the CLI guard, MCP enum and manifest stay in sync from one constant; `delete`/`archive` stay file-only and are refused for folder actions.
16. The folder envelope mirrors `resolveNoteTarget` minus the `.md` rung: vault-relative, realpath inside the vault, not under `Brain/`, vault-scope checks, write binding on the destination, source must stat as a directory, vault root refused. Occupancy pre-flight checks every destination path (plus the dev/ino case-only check) before the first rename and refuses with `destination_occupied` naming every collision and nothing moved. The operation is explicitly not atomic and says so: mid-set I/O failures are recorded in `moveFailures` (rendered `move_failures`), the rewrite pairs are computed from the successfully moved set only, and no rollback is attempted - the settled partial-failure doctrine. Two named additions shipped with it: a mid-set fault that linked the destination name before failing drops that second name (the source still holds the inode; declared in the destructive-sites census beside the prune), and the emptied source directories are pruned bottom-up, with the residue a prune could not remove named in `left_behind`. The refusal vocabulary grew `destination_inside_source` and `move_set_empty` beside `destination_occupied`.
17. One rewrite pass is genuinely complete for folders: a folder move never changes a basename, so bare `[[Name]]` spellings keep resolving and `decideBasename`/`bareNameRepairs` have nothing to do; only path-spelled links break, and a single `retargetWikilinks` call over all pairs (minimal spellings computed against the post-move population) fixes them, including links inside the moved folder. `--expect N` keeps its established meaning - files the apply will write (inbound referers), not files moved.
18. The status `store` group is three-state and fail-soft, wrapped exactly like `writerLockRefusal`: `writerLock: held | free | unknown` (stat failure reads `unknown` with the errno - "could not find out" is not "free"), `writerLockAgeMs` from mtime when held, `writerLockOwner: null` always in v1 (the lock is a bare directory; the renderer states `owner: unknown (the lock record carries no identity)` so absence is a measurement, not a gap), `writerLockPath` in the CLI payload only (withheld below MCP local reach, like `stateFiles.searchIndex`; the follow-up security wave extended the rule - the probe's failure reason is redacted below local reach because the fs error embeds the same path, and the browser explorer is a second below-local surface that withholds the path and scrubs it from the reason), and `thisCaller: "read-only"` with the rendered consequence, scoped to what the lock gates (an index write - `o2b search index` / reindex - while held refuses with `INDEX_LOCKED`; vault and memory writes serialize on the brain lane's own lock files and are not gated by this lock). A held lock is a live writer, not a fault: no problem line, not folded into `healthy` - the `frozen`-field precedent. An injected `writerLockHeldAt` seam (named after `MigrationPlanInput.writerLockHeldAt`) makes the states testable.
19. The `client_versions` probe is manifest-scoped and fail-soft: detection comes from the install manifest like `registered_commands` (a client installed but never registered is out of scope, stated in the docblock); a small constant table maps each target to its version argv (`generic: null`, skipped by name); execution is async spawn inside the existing per-probe timeout so the budget actually covers it; grading is `pass` (exit 0, non-empty stdout - the raw first line, never semver-parsed), `unknown` (throw, non-zero, timeout, empty - ENOENT wording points at `registered_commands` rather than duplicating a fail), or `skipped`; there is no `fail` in v1 because a version row never proves a surface broken. Aggregate and detail follow `probeRegisteredCommands`' shape; the additive optional `rows` field on `ReadinessProbeResult` rides only this probe, so the exit codes are untouched - a fully unknown probe stays exit 6, not 1 - while `readiness_summary` gains the probe's own counts like every probe before it (its `unknown` can read one higher than a pre-1.95 vault's). Binary names beyond `codex` and `copilot-cli` are confirmed against each adapter's detect logic before shipping.

## Risks and open questions

- **Rescue versus tier gate.** The rescue is the only path by which a page crosses tiers; it is bounded by `maxTokens` and priority order, and the top-3 immunity anchors the head. Risk: a rescued peripheral page displacing a would-be core page - bounded because rescue runs after the walker filled every tier-affordable candidate, so only genuinely over-budget candidates compete for freed budget.
- **Skip-reason ripple.** The new `"tail-trim"` reason ripples into the gaps vocabulary; verified that consumers pass reasons through verbatim (`pack-tools.ts:582`) and existing test pins are scenario-specific, not exhaustive over the union. The new reason's pins live in the new tail-trim suite.
- **Marker durability on preference files.** Denials read live frontmatter; `mergeFrontmatterTiered` keeps user-tier keys, and `brain-preference` is in `DEFAULT_TIER_MAP`, so hand-added markers survive framework rewrites. Residual risk is an operator removing a marker to re-share - which is the intended mechanism, not a defect.
- **Byte-identity pressure on the export.** The `export-redaction` fixtures pin "nothing to redact is byte-identical"; the `omitted` field must be absent-when-empty and notices stderr-only, and both properties get their own pins.
- **Presence record volume.** One `reply_presence` record per checked Stop event grows the continuity ledger per turn; bounded and kept-never-fold in v1. If volume proves noisy, the follow-up is a mode, not silent suppression.
- **Join coverage honesty.** Receipts without `receipt_session_id` and presence records without a matching `session_id` read `unjoined`; no time-window inference. Documented in the read-surface help text.
- **Census self-derivation assumption.** Both vocabulary extensions (`ANSWER_QUOTE_VERDICT` + `absent`, `NOTE_LIFECYCLE_ACTION` + two actions) are expected census-silent because census entries derive from the live constants. If either lane discovers a required census edit, it stops and reports rather than editing the shared census file (contract item 6).
