# Delivery trust - implementation plan

Four implementation lanes with strictly disjoint file ownership plus one integrator. Each task is TDD-ready: write the failing test first, implement until green, refactor with all tests green, then run the repo formatter (`./node_modules/.bin/oxfmt`, i.e. what `bunx oxfmt` resolves locally) and the repo lint (`bun run lint`, `oxlint -c oxlint.json`) on the task's own files before every commit, and commit only that task's own files with `git commit --only <paths>` (never a plain `git add` + `git commit`). Each lane runs ONLY its own new or changed test files locally (never the full suite); the integrator runs the full gates. Version bump, CHANGELOG assembly and the release-wide docs pass are the pr-prepare phase and are intentionally absent here.

## Cross-lane contracts (frozen before lane work starts)

These are the pinned shapes every lane builds against. A lane that needs to change one stops and renegotiates in this document first; it never narrows an exported shape unilaterally.

- **K1 - delivery shaping (Lane A owns, nobody else imports).**
  - `src/core/brain/delivery-shaping.ts`: `export const DELIVERY_TREATMENT = Object.freeze({ plain: "plain", fenced: "fenced" } as const)`; `export type DeliveryTreatment = (typeof DELIVERY_TREATMENT)[keyof typeof DELIVERY_TREATMENT]`; `export function isDeliveryTreatment(value: unknown): value is DeliveryTreatment`; `export function shapeStoredTextForDelivery(text: string, opts: { treatment: DeliveryTreatment; origin: string }): { text: string; treatment: DeliveryTreatment }` - `plain` returns the input bytes unchanged; `fenced` returns `fenceUntrustedContent(text, origin)` from `src/core/brain/untrusted-source.ts` (same tag, same neutralization; no new delimiter vocabulary).
  - `src/core/brain/provenance/page-origin.ts`: `export interface PageOriginForDelivery { readonly originChannel: OriginChannelStamp | null; readonly contentClass: string | null; readonly untrustedSource: boolean }`; `export function pageOriginForDelivery(vault: string, rel: string, cache: FrontmatterCache): PageOriginForDelivery` reading only `ORIGIN_CHANNEL_FIELD`, `CONTENT_CLASS_FIELD`, `UNTRUSTED_SOURCE_FRONTMATTER_KEY` via `readCachedFrontmatterEntry`; `export function storedTextTreatment(origin: PageOriginForDelivery | null): DeliveryTreatment` - marker true, or `content_class: prompt-derived`, or channel `mcp-tool`/`import`, or ANY absence (null origin, null channel, `unset`) resolves `fenced`; only channel `cli` with no other marker resolves `plain`; `export function deliveryOriginLabel(origin: PageOriginForDelivery): string` - the fence's `origin` attribute text naming the derived provenance.
- **K2 - receipt verify (Lane B owns; MCP and CLI faces consume exactly this).**
  - `src/core/brain/context-receipts-verify.ts`: `export const RECEIPT_VERIFY_VERDICT = Object.freeze({ match: "match", changed: "changed", unavailable: "unavailable" } as const)`; `export type ReceiptVerifyVerdict = ...`; `export const RECEIPT_VERIFY_UNAVAILABLE_REASON = Object.freeze({ no_path: "no_path", no_hash: "no_hash", file_missing: "file_missing", unreadable: "unreadable" } as const)`; `export interface ReceiptItemVerification { readonly id: string; readonly path: string | null; readonly verdict: ReceiptVerifyVerdict; readonly expectedHash: string | null; readonly observedHash: string | null; readonly unavailableReason: ReceiptVerifyUnavailableReason | null; readonly note: string | null }`; `export interface ReceiptVerification { readonly receiptId: string; readonly createdAt: string; readonly trigger: ContextReceiptTrigger; readonly sessionInjected: boolean; readonly items: ReadonlyArray<ReceiptItemVerification>; readonly counts: { match: number; changed: number; unavailable: number } }`; `export function verifyContextReceipt(vault: string, receipt: ContinuityRecord): ReceiptVerification`. - **K3 - opencode shim relay (Lane C consumes existing shims; no new core exports).** The plugin spawns, through its existing `hookCommand`, `o2b-hook pretool-orient` / `o2b-hook pretool-host-backup` with synthetic payloads `{"hook_event_name":"PreToolUse","session_id":<opencode session id>,"tool_name":<tool>,"tool_input":<args>,"cwd":<dir>}` and `o2b-hook recall-inject` / `nav-inject` / `counterparty-brief` / `reground-deliver` with `{"hook_event_name":"UserPromptSubmit","session_id":<id>,"prompt":<text>,"cwd":<dir>}`. - **K4 - attestation kernel (Lane D owns; CLI and MCP faces consume exactly this).**

Keys under `<vault>/.open-second-brain/keys/attestation/`; private keyfile 0600 with `restrictToOwner` and the sync-exclusion marker; key material never printed.
  - `src/core/brain/attestation/verify.ts`: `export type AttestationShardState = "intact" | "appended" | "diverged" | "missing"`; `export interface AttestationVerification { readonly recordId: string; readonly createdAt: string; readonly signatureValid: boolean; readonly shards: ReadonlyArray<{ readonly shardId: string; readonly state: AttestationShardState }>; readonly storeDigestMatches: boolean }`; `export function verifyAttestation(vault: string, record: AttestationRecord, opts?: { safeguard?: Safeguard; progress?: ProgressSink }): AttestationVerification`.
- **K5 - shared registries are append-only.** Files listed in the shared table below are edited by a lane only in its lane-final task, appends only (never edits, reorders or deletes another lane's entries), and committed in that lane's own final commit via `git commit --only`.
