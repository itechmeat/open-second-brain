# Guarded host writes and surface sweep - consent ladders and a backup hook for host-config writes, cursor pagination for MCP list tools, a Converse decision-model route, and snooze for the trigger queue

**Status:** implemented
**Author:** feature-release orchestrator (via feature-release-playbook)
**Audience:** implementation

## Problem statement

Five triaged cards ship in one wave on one branch (`feat/p4-sweep-guarded-host-writes`), one pull request. They form four work clusters:

1. Host-config write guards (cards t_b6bcd984 and t_f4555087). Three Open Second Brain write lanes modify files that govern an operator's agent client - the install JSON-merge into `~/.gemini/settings.json` and peers, `brain protect --apply` into the project `.claude/settings.json`, and `brain doctor --repair --apply` - and none of them renders a diff of the file, asks for consent, or records whether a human confirmed the write. Separately, nothing on the installed hook surface backs up or receipts agent tool writes to host settings files, so one bad agent write silently changes the client's own behavior with no record of the prior state.
2. Cursor pagination (card t_5198f0c7). Cursor pagination exists on a minority of MCP surfaces while 23 list tools expose `limit` with no continuation cursor, each hand-rolling its own cap; the result is an inconsistent surface where the same operation (walking a large result set) has a first-class answer on some tools and no answer on the rest.
3. Decision-model routing (card t_7ff0b101). The decision-model adapter union is exactly `systemone | vercel-evaluate | llm-emulation`; operators who reach models through a bearer-authenticated Converse-protocol (Bedrock-style) gateway cannot route decision-model calls through it and would have to stand up a separate OpenAI-compatible proxy.
4. Trigger attention (card t_00e9de6a). Open Second Brain's trigger `dismiss` silences a finding for a fixed `TRIGGER_COOLDOWN_DAYS` window regardless of whether the underlying work changed, so a still-broken thing resurfaces on a timer and a genuinely-moved thing stays silent until the clock runs out; there is no "later, but do not lose it" state between open and dismissed.

## Scope

- t_b6bcd984: extend the existing diff-plus-fail-closed-consent patterns to the three unguarded write lanes (install JSON-merge, brain protect, doctor repair) and record the consent verdict in each lane's receipt.
- t_f4555087: an opt-in, default-off, stdlib-only PreToolUse hook that backs up host settings files (with a receipt line) before an agent file-tool write lands, refusing the write when the backup fails.
- t_5198f0c7: one shared offset-cursor helper in core, adopted by the 23 censused limit-only list tools per tier, with recorded decisions where a cursor is deliberately not added.
- t_7ff0b101: a `converse` decision-model adapter module, preset, threshold profile, egress site and contract-suite route for bearer-authenticated Converse-protocol gateways.
- t_00e9de6a: a `snooze` trigger action (bounded window or next refire, whichever comes first) and movement-gated resurrection for dismissed triggers (reopen only on changed `sourceArtifacts`).

## Chosen approach

Variant 3 from the consultant review: cluster-honest sharing with a sequencing contract. The full variant text is in variants.md beside this document.

Machinery is shared only where several real call sites already exist inside one surface, and cross-surface agreements are pinned as contracts instead of imports:

- Inside the trust lane (t_b6bcd984 + t_f4555087), the first commit pins the shared conventions - the consent vocabulary (confirmed, refused, headless-refused), the receipt-line schema (actor, pid, before-hash, summary plus a per-lane tail), and the timestamped backup-folder layout - and moves `renderUnifiedDiff` to a core leaf. The three write lanes (install JSON-merge, protect, doctor repair) consume those conventions directly; the standalone PreToolUse hook is pinned to the same receipt contract by a fixture test rather than an import, so the hook stays stdlib-only.
- Inside the pagination lane (t_5198f0c7), the first commit extracts one pagination helper in core, standardizing on the required-`next_cursor` precedent, and the 23 tools adopt it per tier.
- After those two lane-internal commits, all lanes run in parallel under one ordering rule inside the trust lane (on the shared write path: consent, then backup, then write).
- The Converse adapter lane and the trigger lane share nothing with the others: the adapter composes the existing transport helpers beside `vercel-evaluate`, and the trigger lane touches only the trigger store and its CLI/MCP projections.

## Design decisions

1. The consent ladder is fail-closed on `--json`/non-TTY, copying the canonical pattern at src/cli/brain/verbs/upgrade.ts:119-137: without `--yes`, a `--json` or non-TTY stdin call refuses (naming `--yes` and the non-interactive mode); with a TTY it prompts once y/N via `readSingleLine`. Applied to `install --apply`, `protect --apply` and `doctor --repair --apply`. A consent gate sits above the write guard and never gates dry runs (src/core/brain/applier-capability.ts header; diagnostics.ts:1490-1495 convention).
2. Consent composes with the existing drift guard, never replaces it: the `_json-mcp.ts` refusal of drifted config (src/core/install/adapters/_json-mcp.ts:328-349) still fires on an explicit yes, and its refusal still names its remedy. The three lanes keep their distinct no-semantics (install aborts the target, protect refuses the apply, doctor skips per fix) rather than one flattened gate.
3. MCP `brain_doctor` `apply: true` stays machine consent: no new required argument (that would break agents mid-flight and drift the tool description quoted in host listings). The MCP path records verdict provenance `caller-apply` in the doctor-repair event body; CLI paths record `yes-flag` or `interactive-yes`.
4. Receipts are per-lane and stay in each lane's existing receipt channel. Doctor repair has a Brain typed log event: its body (src/core/brain/diagnostics.ts:1542-1546, kind doc src/core/brain/types.ts:496-506) gains a consent field. Install and protect keep no event log at all: their receipts are the CLI apply JSON payloads (additive keys under `INSTALL_JSON_SCHEMA_VERSION = 1`) and the install sidecar manifest. The consent verdict does NOT go into the sidecar manifest - it is a schema'd sidecar with `applied_at` semantics (src/core/install/adapters/_json-mcp.ts:363-377); the verdict belongs in the CLI JSON receipt.
5. The PreToolUse host-settings backup hook is opt-in with default OFF via `resolveConfigFlag` in src/core/config.ts (env `OPEN_SECOND_BRAIN_HOST_SETTINGS_BACKUP` overriding the `host_settings_backup` config key, beside `resolveHookStrictEnabled` at lines 1597-1603), and stdlib-only: the hook wrapper imports no core module, so a broken or absent core install cannot turn a failed backup into a failed hook load. Because the `scripts/o2b-hook` dispatcher is deliberately fail-soft (suppresses non-zero exits, always exits 0), the deny channel is stdout `hookSpecificOutput.permissionDecision: "deny"` (the `emitPermission` pattern, hooks/pretool-orient.ts:127-136), and the honest limitation - no deny at all when bun or the hook script is missing - is documented in the hook docblock and hooks/README.md.
6. Trust-lane sequencing: conventions and the diff leaf land first, then the three write lanes, then the backup hook. On the shared write path the order is consent, then backup, then write; a refused consent must not leave a backup file.
7. The pagination helper lives in core (src/core/brain/offset-cursor.ts) and the 23 censused limit-only tools adopt it per tier: 12 Tier-A ordered logs get full cursor walks; 9 Tier-B diagnostics get either a cursor (where the output is an ordered walk, `brain_session_grep`) or a recorded report-cap decision written beside the census tests; 2 Tier-C ranked retrieval (`brain_search`, `brain_file_context`) stay limit-only with the ranking-stability rationale pinned as a census entry. The canonical encoding is the receipts.ts:515-531 base64url form (the oldest, already malformed-cursor-tested); existing encodings on decisions history, session expand and continuity do not change.
8. `next_cursor` is present in every adopting tool's answer, `null` when exhausted - the required-field treatment of `brain_search_expand` is the precedent, because an optional field some tools omit recreates the inconsistency this card exists to remove. Existing count fields (`total`, `returned`, `total_pages`) are kept; the new field is additive.
9. The four census tests - tests/mcp/agent-scope-matrix.test.ts, tests/core/architecture/visibility-surface-census.test.ts, tests/core/brain/continuity/reader-census.test.ts, tests/mcp/maintenance-parity-census.test.ts - are updated in the SAME commits that change the surfaces they census. A census update deferred to a later commit is a broken bisect and a failed review.
10. The openclaw bundle (openclaw/index.js, a committed build artifact that transitively embeds `EGRESS_SITES`) is rebuilt by the integrator as the LAST commit after any `src/` edit, so the CI bundle diff passes exactly once.
11. The trigger snooze window is a `TRIGGER_SNOOZE_DAYS` constant beside `TRIGGER_COOLDOWN_DAYS` (src/core/brain/triggers/store.ts:60-62), not a config key in this wave: Lane A owns src/core/config.ts and no other lane touches it. A config key is a recorded follow-up.
12. Settled trigger semantics: snooze wakes at window end or next refire, whichever comes first (refire read from the existing `recordRecurrence` ledger as `lastSeenAt > snoozedAt`, which requires `blockReason` to keep returning a reason for snoozed twins so the ledger keeps stamping); a dismissed twin reopens only on changed `sourceArtifacts` (an order-insensitive set comparison following the `deriveDatasetHash` convention, src/core/brain/derived-artifact.ts:44 - movement is the detector firing on different artifacts, never `lastSeenAt` alone); `suppress` stays clockless; `snoozed` joins the terminal status partition (mirroring `suppressed`, so the brief allow-list excludes it with zero brief changes and the TTL expiry clock never governs the snooze wake); resurrection arrives as a new pending record through `createTriggersLocked`, never as a status flip of the resolved record.
13. Lane file ownership is disjoint and listed under File changes; `src/core/config.ts` is owned by Lane A only.

### t_f4555087 - back up host settings before agent tool writes

**Card ask.** A fail-closed PreToolUse gate that fires on file-tool calls targeting the host client's personal settings files: it resolves tilde, relative paths and symlinks, copies the file into a timestamped backup folder, appends one receipt line (actor, pid, before-hash, summary), and only then allows the write - a failed backup refuses the call. Upstream is fail-closed and stdlib-only and never overwrites a same-second backup; the Open Second Brain version is an opt-in extra entry in hooks/hooks.json.

**Premise verdicts (recon-verified).**

- CONFIRMED - deny rules cover only Brain dirs plus the brain config: `buildProtectRules` at src/core/brain/protect.ts:109-130 (`Brain/preferences/**`, `Brain/retired/**`, `Brain/log/**`, `Brain/.snapshots/**`, `brainConfigPath(vault)`; allow `Brain/inbox/**`). Nothing outside the vault is covered.

- CORRECTED (detail; essence holds) - hooks/hooks.json registers nine event families (PostToolUse, SessionStart, UserPromptSubmit, PreToolUse, Stop, SubagentStart, SubagentStop, SessionEnd, PostCompact), not just the three the card lists. - CONFIRMED - nothing backs up or receipts tool writes to `~/.claude/settings*.json`: the only `settings.json` hits in src and hooks are install adapters resolving their own declared targets and protect writing the vault's own `.claude/settings.json`. No `host_settings` concept exists anywhere.

**Settled design.**

**Feature-specific risks.** Fail-closed has a hard floor (missing runtime silently no-ops - documented, not hidden). Symlink and temp-then-rename targets can see the hook back up one path while the write lands on another - stated honestly in the README.
